# 极客跳动 AI 运营中心｜V1.3 本地交付说明

- 日期：2026-08-18
- 状态：本地实现候选；未提交、未推送、未部署
- 范围：LinkedIn 第七渠道、五平台统一扩展、七渠道定时任务、保留多账号正式发布

## 1. 已实现

- Shared、内容引擎、API、数据库、Worker 与 Web 已识别 `linkedin`。
- LinkedIn 生成独立文章产物，面向企业决策者，支持 3–5 个话题标签。
- 小红书、知乎、今日头条、百家号、LinkedIn 共用 Chrome 扩展 `1.4.0`。
- 扩展增加 LinkedIn 文章入口、标题/正文/账号识别、草稿与发布动作、安全停止及结果回传。
- 内容生产、人工复核、任务详情、渠道管理、定时任务和多账号发布均展示 LinkedIn。
- 定时任务支持全部七渠道；Worker 固定 `requireReviewBeforeDraft=true`，触发后只生成复核稿。
- 多账号草稿与正式发布保留；正式发布继续要求账号匹配、内容指纹、完整标题和二次确认。
- 数据库旧渠道约束具备幂等迁移，可连续执行。

## 4. 部署与回滚

部署前：

1. 备份 PostgreSQL，并记录当前镜像和扩展安装包校验值。
2. 执行迁移预检，确认 `linkedin` 已进入渠道约束。
3. 核对生产环境的扩展最低版本为 `1.4.0`。
4. 禁止把测试账号、Cookie、令牌或真实密钥写入代码、日志或文档。

部署后：

1. 检查 readiness、Worker release、七渠道健康和扩展下载地址。
2. 用测试内容验证七渠道定时任务只进入人工复核。
3. 逐渠道完成草稿验收；正式发布只用经批准的测试文章和账号。
4. LinkedIn 页面无法唯一识别按钮、账号或成功信号时必须停止，不得盲目重试。

回滚时恢复上一镜像和上一扩展包；数据库迁移为向前兼容新增约束，不删除 LinkedIn 历史记录。若平台 DOM 变化，只停用对应浏览器渠道，不影响官网、公众号及其他渠道。
