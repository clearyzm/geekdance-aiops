# 自包含视觉质量门

## 原则

强制客户可见结果达标，不强制所有低风险任务加载同一专家。本Skill、Taste与Impeccable均随项目分发；两位专家提供方向和专项审查，但不替代本结果门。

开始前读取：

- experience/EXPERIENCE.md
- docs/PRODUCT.md
- docs/PROJECT-ADAPTATION.md
- docs/PAGE-INTERACTIONS.md
- docs/PROJECT-STATUS.md
- 当前端SPEC和既有设计系统

## 路由

| 页面 | 模式 | 专项原则 |
|---|---|---|
| 官网、落地页、商品、定价 | Persuade | 信任、差异化、价值层级、行动路径 |
| Portal、工作台、订单、表单 | Operate | 任务效率、认知负荷、反馈、恢复 |
| Admin、数据表、审核、配置 | Operate | 扫描、比较、批量操作、密度 |
| 文档、帮助、文章 | Read | 阅读节奏、目录、行长、代码与图表 |
| 作品展示、沉浸内容 | Experience | 叙事、节奏、内容主导、克制动效 |

风险：

- L0：纯文案或严格复用已批准组件的微调。
- L1：成熟设计系统内的常规新页面。
- L2：新项目、客户关键页面、无成熟设计系统或显著改版。
- L3：品牌首页、关键转化、投标演示、客户曾否决或首轮不通过。

L2/L3必须加载项目内匹配的design-taste-frontend或impeccable；缺失时视为安装缺陷，不静默降级。L0/L1可记录理由后不加载专家。

调用Impeccable时，在OPD项目根目录设置`IMPECCABLE_CONTEXT_DIR=docs`运行其context.mjs，确保读取docs/PRODUCT.md；随后按任务读取一个Playbook，并在编辑UI前读取reference/craft-floor.md。

## 设计流程

1. 确认目标客户、品牌资产、真实内容、参考和反例。
2. 在PAGE-INTERACTIONS写明Surface、模式、风险、第一印象目标、3秒层级、关键词、密度、动效、图片策略、设备和目标分数。
3. 审计并复用现有设计系统；不存在时先建立颜色、字体、间距、圆角、边框、阴影和核心组件令牌。
4. L2/L3先做一个核心桌面Frame与移动Frame；L3同时提出一个明显不同的备选方向。
5. 用最短、典型、最长真实内容设计；覆盖适用的加载、空、错、无权限、禁用、确认和成功状态。
6. 基线通过后复用令牌和组件扩展页面。
7. 原型与代码分别截图，由独立审查轮检查后集中修复，再截图确认。

## 工艺底线

- 每页只有一个清楚主焦点和主动作；3秒内可判断页面用途和下一步。
- 排版层级来自字号、字重、行高、色阶与留白，不靠堆卡片。
- 使用稳定的间距节奏和内容宽度；对齐误差、孤立标签、拥挤按钮和无意义空白必须修复。
- 不默认使用紫色渐变、发光、玻璃卡片、大面积装饰或相同圆角卡片墙。
- 组件库默认主题不是客户品牌；不得虚构Logo、资质、客户、销量、价格和业务指标。
- 营销页可有明确视觉签名；Admin和任务页优先信息密度、扫描效率与状态清晰。
- 同时检查桌面与移动、浅深主题、键盘、对比度、44px触控目标和reduced-motion。

## 评分与通过

总分100：

- 品牌匹配与信任感20
- 信息层级与易读性20
- 构图与整体美感20
- 组件一致性与细节15
- 响应式与可访问性15
- 真实内容与状态完整性10

客户可见Surface至少85分，内部Surface至少80分。前三项任一低于其满分60%直接失败。必须附桌面与移动截图、逐项分数、主要问题和修复记录；用户明确否决时无条件失败。

## 完成证据

在docs/PROJECT-STATUS.md的“视觉质量证据”表填写VQ行，并运行：

python3 .agents/skills/visual-quality-gate/scripts/validate_visual_quality.py . --stage p2

脚本通过只证明证据结构完整，不证明设计本身美观。没有截图、独立审查和修复闭环时不得标记P2、T1或E2视觉通过。
